# Ianz Fitness

一个可以安装到手机主屏幕的网页 App（PWA）。内置「3 个月力量训练挑战计划」（5/3/1，一周四练），根据你的身体数据、最大重量、伤病、器械和动作偏好，生成每天的训练和营养计划。可以只在本机使用，也可以用邮箱 / 手机验证码注册账号，把数据保存到云端。

## 界面

底部是悬浮导航栏，右边有一个蓝色的圆形「训练」按钮：

| 页面 | 内容 |
|---|---|
| **训练** | 饮食记录（蛋白 / 碳水 / 脂肪 / 饮水 圆环 + 早餐、午餐、晚餐、加餐、饮水、记体重快捷入口）、今日训练、本周安排、饮食建议 |
| **挑战** | 3 个月力量挑战：完成进度环、TM 表、12 周计划和每次训练的完成标记 |
| **动作** | 动作库：左侧部位分类，顶部器械筛选，搜索，「讲解」动作要点，练过的次数，❤️ 喜欢 / 🚫 不做，添加自定义动作 |
| **历史** | 训练记录（日历 + 按周列出）和数据分析（力量曲线、训练量、体重） |
| **我的** | 个人资料、训练设置、营养目标、提醒、数据备份 |
| **训练（圆形按钮）** | 进入训练模式：逐组打勾，自动开始组间休息计时（主项 3 分钟，第二主项 2 分钟，辅助 75 秒），可 +30 秒或跳过 |

饮食记录：点早餐 / 午餐等，可以「按建议记录」，也可以点常见食物一键添加（鸡蛋、鸡胸肉、米饭、蛋白粉等），或自定义输入蛋白、碳水、脂肪克数。

## 账号与云同步（可选）

用 [Supabase](https://supabase.com)（免费）提供验证码登录和云端保存。没有配置时，App 只把数据存在手机本地。

1. 在 supabase.com 注册并新建项目（地区建议选 Singapore 或 Tokyo）
2. **SQL Editor** → 粘贴 `supabase/schema.sql` → Run（建表，并设置“每个人只能读写自己的数据”）
3. **Authentication → Email Templates → Magic Link**，把邮件内容改成包含验证码，例如：
   `<h2>Ianz Fitness 登录验证码</h2><p>你的验证码是：<b>{{ .Token }}</b>，10 分钟内有效。</p>`
4. Supabase 自带的邮件服务每小时只能发很少几封，给朋友用之前，在 **Project Settings → Authentication → SMTP Settings** 配置自己的发信邮箱（例如 QQ 邮箱 / 163 邮箱的 SMTP，或 Resend）
5. **Project Settings → API**，把 Project URL 和 anon public key 填到 `js/config.js`
6. 手机号登录：在 Authentication → Providers → Phone 里接入短信服务商后，把 `js/config.js` 里的 `phone` 改为 `true`

登录方式：第一次用邮箱验证码登录（自动注册），之后会要求设置一个登录密码（至少 12 位，包含字母、数字和特殊字符），以后可以选「密码登录」或「验证码登录」。忘记密码时用验证码登录，再到「我的 → 账号与同步」重新设置。

Google 一键登录：
1. [Google Cloud Console](https://console.cloud.google.com/) 新建项目 → **APIs & Services → OAuth consent screen**，选 External，填写 App 名称 Ianz Fitness 和邮箱，发布（Publish app）
2. **Credentials → Create credentials → OAuth client ID**，类型选 **Web application**；**Authorized redirect URIs** 填 `https://<你的项目>.supabase.co/auth/v1/callback`
3. 把生成的 Client ID 和 Client secret 填到 Supabase **Authentication → Sign In / Providers → Google**，打开开关并保存
4. Supabase **Authentication → URL Configuration**：Site URL 填 App 网址；Redirect URLs 添加 `https://ethanzhengy.github.io/**`

同步规则：每次修改后自动上传，打开 App 时拉取最新数据，以最后修改的一份为准。如果一台手机上已经有数据、而账号在云端也有数据，会询问保留哪一份。退出登录会清除这台手机上的数据（云端保留）。

## 朋友（一起练）

首页右上角「朋友」：
- **联系人**：每个人有一个 6 位好友码和邀请链接（`…/ianz-fitness/?add=好友码`）。朋友输入好友码或点链接后发出请求，你同意后成为好友
- **朋友圈**：你和好友最近 3 天的训练（训练名称、动作数、组数、最重一组），可以互相点 💪 加油。在 App 里完成训练会自动发布，撤销完成会自动撤回
- **权限设置**：可关闭「向好友分享我的训练」。身体数据、饮食、完整训练记录和邮箱永远不会给好友看

需要在 Supabase → SQL Editor 运行一次 `supabase/friends.sql`。

## 第一次打开：问卷

1. **基础信息**：性别、年龄、身高、体重、活动量、目标（增肌 / 减脂 / 维持）→ 用来算营养
2. **身体与器械**：伤病部位（肩 / 腰 / 膝 / 肘 / 手腕），健身房还是家里，有哪些器械
3. **主项与最大重量**：推举、硬拉、卧推、深蹲。填「重量 + 能做几次」，自动估算 1RM，TM = 1RM × 90%
   - 根据伤病和器械自动推荐替代动作，例如腰不好：传统硬拉 → 六角杠铃硬拉，站姿推举 → 坐姿推举
4. **训练安排与偏好**：选 4 个训练日、训练时间、从第几周开始；给动作点 ❤️ 喜欢 / 🚫 不做，也可以手动添加你习惯的动作
5. **生成计划**：显示 12 周的 TM、本周的训练和每日营养目标

之后随时可以在「我的 → 重新填写问卷」修改。

## 每天使用

- **今天想练什么**：默认按固定周期推荐（⭐），也可以按状态自己选推举日 / 硬拉日 / 卧推日 / 深蹲日 / 休息
  - 比如周一选了深蹲，周二不会再推荐硬拉（避免连续两天练下肢），本周剩余的训练会自动重新排
  - 训练日不够时会提醒补练；实在练不完，可以在「挑战」里把整个计划顺延一周
- **今天状态**
  - 💪 很好：带 "+" 的组可以多做几次
  - 🙂 正常：完全按计划
  - 😮‍💨 疲劳：跳过 100% / 110% 单次组，"+" 组只做规定次数，第二主项减到 3 组、重量降 10%，辅助只做 1 个
  - ⏱ 时间紧：只做主项和第二主项
- 每一组打勾记录；"+" 组可以填实际次数，自动估算 1RM
- 辅助动作可以点「换一个」
- **第 12 周**：按预估 1RM 给出热身和试举重量，填入新 1RM 后，下一轮 TM 自动更新

## 已经练了几周？导入进度

问卷第 4 步选「我已经在练了」，再选本周是第几周：
- 之前的周会自动标记为 **📝 App 外完成**（橙色虚线标记）
- 本周已经练过的训练可以直接勾选
- 之后在「挑战」里每一次训练都能「标记 App 外完成 / 取消标记」；「训练」页也能标记本周在 App 外练过的训练

在 App 里完成的训练显示 **✓ App 完成**（蓝色），漏掉的显示「未完成」。App 外的训练按计划重量估算训练量，不参与估算 1RM。

## 数据分析（📈 数据）

- 概览：累计训练次数（App / App 外）、连续完成周数、本轮完成率、总训练量（吨）
- 力量曲线：每个主项的 TM 阶梯线、"+" 组算出的估算 1RM、第 12 周测试的 1RM，以及相对起始 1RM 的提升；点任意数据点看详情，可展开数据表
- 每周训练量柱状图（App 记录 / App 外估算分色）
- 训练日历热力图 + 每周完成情况
- 最近训练记录（最重组、估算 1RM、训练量）
- 体重记录与曲线（同时更新营养目标）

## 训练计划规则（来自原计划图片）

| 周 | 主项 | 第二主项 | 其他 |
|---|---|---|---|
| 1 | 70/80/90% × 3，最后一组 3+，再加 100% × 1 | 70% × 5 组 | 拉类 / 核心 5 组 |
| 2 | 65/75/85% × 5 | 65% × 5 组 | 5 组 |
| 3 | 75/85/95% × 5/3/1+，再加 100% × 1 | 75% × 5 组 | 5 组 |
| 4 | 减载 50/60/70% × 5 | 50% 3 × 10（硬拉 3 × 8） | 3 组 |
| 5 | TM 加重；70/80/90% × 3，再加 100% 全力组 | 70% × 3 组 | 3 组 |
| 6 | 65/75/85% × 5 | 65% × 3 组 | 3 组 |
| 7 | 75/85/95% × 5/3/1，再加 100% 全力组 | 75% × 3 组 | 3 组 |
| 8 | 减载 | 50% × 3 组 | 3 组 |
| 9 | TM 加重；70/80/90% × 3，再加 100% 和 110% 各 1 次 | 70% × 3 组 | 3 组 |
| 10 | 65/75/85% × 5 | 65% × 3 组 | 3 组 |
| 11 | 75/85/95% × 5/3/1 | 无 | 不做任何辅助 |
| 12 | 极限测试：硬拉、卧推、深蹲（推举可选） | | |

- 补充说明：
  - 每周的训练组合：周一推举 + 卧推，周二硬拉 + 深蹲，周四卧推 + 推举，周五深蹲 + 硬拉。
  - 第二主项为硬拉时，每组 5 次；其他第二主项每组 5–8 次。
  - 推举不做 100% / 110% 单次组，改为最后一组做 "+"。
- TM 加重：第 5、9 周上肢 +2.5kg、下肢 +5kg。
- 重量算法：所有重量按 TM × 百分比计算，再四舍五入到你的最小加重单位。原图片里有几处手算错误（例如第 10、11 周卧推），这里以公式为准。

## 辅助动作怎么分配

根据当天主项和第二主项已经练累了哪些部位来挑选，例如：
- **推举日**：优先后束、二头和水平划船。
- **卧推日**：优先三头和垂直拉。
- **硬拉日**：后链已经很累，所以不安排早安式这类压腰的动作，核心练抗伸展、抗旋转。
- **深蹲日**：优先腘绳肌、小腿和握力。

另外几条规则：
- 第二天是下肢日时，前一天少安排压腰的动作。
- 有腰伤时，不会自动安排压腰的动作。
- ❤️ 的动作优先、经常出现；🚫 的动作和器械做不了的动作不会出现。
- 同一天不会安排两个同部位的辅助动作，每周轮换以保持多样性。

## 营养

基础代谢用 Mifflin-St Jeor 公式计算。每日热量按天的类型区分：

- **下肢大重量日**：最高，碳水最多。
- **上肢日**：其次。
- **休息日**：最低。

蛋白质按 1.8–2.2 g/kg 计算，脂肪约 0.8–1.0 g/kg，剩余热量给碳水。练前加餐和练后餐会按你的训练时间安排。

## 安装到手机

把仓库发布到 GitHub Pages（Settings → Pages → 选择分支和根目录），用手机打开网址：
- iPhone：Safari → 分享 → 添加到主屏幕
- Android：Chrome → 菜单 → 安装应用

本地运行：`python3 -m http.server 8000`，然后打开 http://localhost:8000
